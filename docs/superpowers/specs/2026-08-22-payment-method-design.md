# 記帳付款方式移植設計

## 目標

將 `E:\My build\kr_travel-manus` 中記帳功能的付款方式移植至目前專案，維持既有支出、分帳、匯率與自定類別功能不變。

## 範圍

付款方式功能包含：

- 在 `Expense` 資料模型加入可選的 `paymentMethod` 欄位，確保既有 IndexedDB 資料與備份仍可讀取。
- 提供來源專案相同的 11 種付款方式：現金、信用卡、簽帳金融卡、Google Pay、Apple Pay、Samsung Pay、LINE Pay、銀行轉帳、交通卡、QR Code 支付、其他。
- 在新增／編輯支出表單加入付款方式選擇，新增支出預設為現金，編輯舊資料時載入既有值；未知或無效值正規化為「其他」。
- 在支出列表顯示已設定的付款方式。
- 提供依付款方式篩選，並保留「未設定」選項以處理舊資料。
- 加入付款方式統計區塊，顯示目前類別範圍的總額、筆數與比例；點擊統計卡片可切換付款方式篩選。
- 補齊表單、頁面與付款統計的元件測試。

不包含付款方式自訂管理、資料庫版本升級、其他來源專案功能或與本需求無關的重構。

## 設計

### 資料模型與相容性

在 `src/domain/types.ts` 新增 `PaymentMethod` union type，並在 `Expense` 加入 `paymentMethod?: PaymentMethod`。欄位保持 optional，讓目前資料庫中沒有付款方式的資料不需遷移即可使用。備份格式沿用目前的整筆 Expense JSON，不增加 schema 版本；匯入舊備份時缺少欄位即視為未設定。

在 `src/features/expenses/paymentMethods.ts` 集中管理付款方式選項、顯示名稱與正規化函式，避免表單、列表與統計各自維護一份 mapping。

### 使用者流程

表單會在類別／付款人欄位附近提供付款方式下拉選單。儲存時把選定的 ID 寫入 `Expense`；編輯時以既有 ID 初始化。列表篩選先套用類別，再套用付款方式。類別範圍改變時，統計重新計算；目前篩選狀態保留，若選中的方式在新範圍沒有資料則顯示空結果。

付款統計使用 `baseAmountMinor` 計算，依付款方式分組並顯示金額、筆數與佔目前範圍總額比例。未填寫付款方式的資料會獨立歸入「未設定」，不強制回填舊資料。

### 元件與樣式

- `PaymentMethodSummary.tsx`：純展示與篩選回呼，負責計算付款方式統計。
- `paymentMethods.ts`：付款方式型別衍生的選項與工具函式。
- `ExpenseForm.tsx`：加入付款方式欄位與儲存／編輯初始化。
- `ExpensePage.tsx`：加入付款方式篩選、統計、列表標籤與篩選狀態。
- `src/styles/app.css`：加入篩選列、統計卡片與付款方式標籤樣式，沿用現有主題 token 與手機版排版。

### 錯誤處理

付款方式本身不需要網路請求。未知資料值不讓頁面崩潰，而是以「其他」顯示；缺少欄位以「未設定」顯示。既有匯率、金額與分帳驗證維持原樣。

## 驗收條件

1. 新增支出可選付款方式並儲存，重新開啟編輯時值正確保留。
2. 舊有沒有 `paymentMethod` 的支出仍可載入、顯示與編輯。
3. 列表會顯示付款方式，未知值不造成錯誤。
4. 類別與付款方式篩選可同時作用；「未設定」可篩出舊資料。
5. 統計金額、筆數與比例以目前類別範圍正確計算，點擊卡片能同步切換篩選。
6. `npm test`、`npm run lint`、`npm run build` 通過。
